# Intelligent Analytics Query Engine

A schema-driven natural-language analytics engine for CSV datasets. It converts business questions into validated read-only DuckDB SQL, executes the SQL deterministically, and returns result + confidence + explanation.

## Why this design

The engine is intentionally **not** a collection of hard-coded answers. It has separate layers:

1. **Data loader** — detects and repairs the assignment's quoted-single-field CSV format, infers basic types, and validates rows.
2. **Catalog / semantic layer** — exposes table schemas, samples, metrics, dimensions, synonyms, and time mappings to the planner.
3. **GenAI planner** — converts natural language into a small SQL plan. The model sees the live schema instead of a fixed schema.
4. **SQL safety gate** — only SELECT/WITH statements are accepted; DDL/DML and unknown tables are rejected.
5. **DuckDB executor** — performs aggregation, grouping, filtering, joins, window functions, nested queries, percentages, and time logic deterministically.
6. **Response layer** — returns the requested query, generated logic, result, confidence score, explanation, and assumptions.

This separation is what makes the system more resilient to new data files and unseen queries.

## Run

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env   # Windows
# cp .env.example .env  # macOS/Linux

py -3.11 -m pip install -r requirements.txt
py -3.11 -m uvicorn app.main:app --reload
py -3.11 -m pytest -q
```

Put an Google Gemini API key in `.env` to enable general natural-language planning:

```env
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-3.8-flash
```

Without a key, the included benchmark queries work through an offline deterministic fallback, but arbitrary new questions require the GenAI planner.

Copy `.env.example` to `.env` and replace the placeholder with a real key. The key is loaded only from the environment and is never included in responses or sample outputs.

## Data contract

Drop CSVs into `data/`. The loader creates table names from filenames. A `data_dictionary.json` is optional, but recommended because it gives the model business semantics that raw column names cannot provide.

For a new dataset, you do **not** change executor code. The catalog automatically inspects columns and supplies the schema to the planner. If business meaning changes, update the dictionary rather than adding query-specific code.

## Important behavior

- No answer values are hard-coded.
- The LLM never directly executes arbitrary Python.
- SQL is generated by the planner and then validated before execution.
- YoY and similar comparisons do not invent missing history.
- Multiple tables can be queried when their schemas support a sensible join.
- The current benchmark data contains only 2024 sales, so YoY growth has no prior-year comparison; the engine returns null prior-year values instead of fabricating growth.
- Confidence starts with the planner's structured score and is reduced when explicit assumptions are required. Successful SQL validation and DuckDB execution verify the referenced tables and columns.

## Tradeoffs

DuckDB was chosen over ad-hoc pandas code because SQL naturally expresses joins, window functions, nested aggregation, ranking, and percentages while remaining fast for CSV-scale analytics. The semantic dictionary remains external so business definitions can evolve without changing execution code.

The main remaining production hardening step would be a stronger structured-output schema for the LLM and a query-plan validator that checks every referenced column against the catalog before execution.

## Gemini availability

The planner treats Gemini as a planning service, not as the database engine. Temporary 429/5xx responses are retried with a short exponential backoff. If the configured model remains unavailable, the planner tries the models listed in `GEMINI_FALLBACK_MODELS` before using the local benchmark fallback.

Example `.env`:

```env
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.8-flash
GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.6-flash
```

To verify the configured key, SDK, and model with a real request:

```bash
python -m app.gemini_diagnostic
```

The application never fabricates a result when neither Gemini nor the local planner can safely interpret a query.
